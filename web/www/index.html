Frequently asked questions

    

      What is an InstallScript decompiler?
      
InstallShield installers are driven by scripts written in InstallScript (.rul files). The installer ships them compiled — usually as an encrypted setup.inx. A decompiler reads that compiled form and reconstructs InstallScript source you can read, so you can see what an installer does before or after running it.

    

    

      Where do I find setup.inx?
      
Programs installed with InstallShield keep a copy under C:\Program Files (x86)\InstallShield Installation Information\{product GUID}\setup.inx. For an installer you haven't run, extract setup.exe (or look next to it on the installation media) — setup.inx sits alongside data1.cab and setup.ini. Older InstallShield 5 installers use setup.ins instead.

    

    

      Which files are supported?
      
Compiled setup scripts (setup.inx) from InstallShield 6 and later, compiled script objects (.obs), script libraries (.obl, each member is decompiled in turn) and InstallShield 5 scripts (setup.ins). Scripts compiled with debug information are not supported yet.

    

    

      Is my file uploaded anywhere?
      
No. The decompiler is written in Rust and compiled to WebAssembly; it runs inside your browser in a background worker. Your file never leaves your computer.

    

    

      Why does the output look different from the original source?
      
Compilation throws away comments, formatting and the names of local variables and non-exported functions, so those come back as generated names like LclVarNum1 or Func_2047. Loops come back as gotos. Decompilation is not perfect — if a file produces wrong output, please open an issue.

    

    

      Can I use it from the command line?
      
Yes. The same decompiler is available as an open-source command-line tool — see the GitHub repository.
